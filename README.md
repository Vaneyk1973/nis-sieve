# nis-sieve

Проект команды 12 НИС «Распределённые системы 2»: независимые реализации
SIEVE, LRU и ARC в общем симуляторе кэша, сравнение доли промахов и
служебных операций на открытых трассах.

- [Назначенное задание P05](https://distsys.ru/osukhoroslov/nis2/src/branch/main/project-tasks/p05-sieve.md).
- Участники: Смирнов Глеб, Смирнягин Артём, Хмура Иван.
- ARC — третья политика; окончательное распределение следующих задач команда
  подтверждает перед сдачей.

## Окружение и проверка КТ1

Нужны Docker Engine и доступ к сети при первой сборке. Из корня репозитория:

```sh
docker build -t nis-sieve:dev .
docker run --rm --network none \
  --user "$(id -u):$(id -g)" \
  --mount "type=bind,src=$PWD,dst=/workspace,readonly" \
  nis-sieve:dev python3 tests/check_environment.py
```

Ожидаемый итог: `ALL CHECKS PASSED`. Проверка компилирует маленькую программу
через Meson, запускает авторский эталон на известных входах, собирает и
тестирует прототип ARC и сверку с эталоном, проверяет чтение CSV и согласованность аналитического
журнала служебных операций. Она работает
без сети, создаёт промежуточные файлы только во временном каталоге контейнера.

В образе: GCC 16.2.0, Meson 1.12.1, Ninja, Python 3, CMake и зависимости
libCacheSim. Авторский артефакт закреплён на
`0861f8261c37b8286a70449a1defb5a4749c72d2` и находится в `/opt/sieve-reference`.
В его CLI добавлен только вывод существующих целых счётчиков запросов и
промахов (`EXACT`); алгоритмы политик не изменялись. Это позволяет проверять
равенство без потери точности при округлении доли промахов.
Команда `cachesim` доступна в `PATH`. Из собственных политик пока есть только
[прототип ARC](prototypes/arc).

Для работы с будущим кодом и записью файлов в репозиторий:

```sh
docker run --rm -it --user "$(id -u):$(id -g)" \
  --mount "type=bind,src=$PWD,dst=/workspace" nis-sieve:dev
```

Проверка на настоящем трейсе скачивает `meta_reag` (334 МБ, нужна сеть), берёт
первые 5 млн запросов и сравнивает прототип ARC с эталоном, при расхождении
завершается с ошибкой. Нужно около 1,5 ГБ
на диске и 1 ГБ памяти:

```sh
docker run --rm --memory 1g --memory-swap 1g --user "$(id -u):$(id -g)" \
  --mount "type=bind,src=$PWD,dst=/workspace" \
  nis-sieve:dev bash tests/check_real_trace.sh
```

## Повторить большие проверки

После сборки образа из корня репозитория:

```sh
docker run --rm --cpus 2 --memory 3g --memory-swap 3g \
  --user "$(id -u):$(id -g)" \
  --mount "type=bind,src=$PWD,dst=/workspace" \
  nis-sieve:dev python3 tests/check_large_traces.py
```

Сценарий проверяет первые 10 млн запросов Meta CDN `meta_reag`, Twitter
`cluster10` и Wikimedia `wiki_2019t`. Шесть ёмкостей: 0,1%, 0,3%, 1%, 3%, 10%
и 30% уникальных объектов. Запускаются собственный ARC и авторские
FIFO/LRU/SIEVE/ARC: 90 запусков политик и 18 точных сверок собственного ARC.
Это холодный старт без прогрева, проверка стенда, а не полная серия проекта.

Первый запуск требует сети и потоково загружает только нужные префиксы;
полные архивы не сохраняются. Для каждого префикса проверяются 240 млн байт
и закреплённый SHA-256. Готовые входы хранятся в игнорируемом Git каталоге
`data/`; повторный запуск использует их после проверки хеша и работает с
дополнительным флагом Docker `--network none`. Нужен примерно 1 GiB диска
помимо образа. Неверный кэш вызывает ошибку, а не незаметную замену данных.

Ожидаемый итог: `ALL LARGE TRACE CHECKS PASSED: 18 exact ARC comparisons`.
Сценарий перезаписывает свои сгенерированные результаты в
[nis/checkpoints/01-results/large-traces](nis/checkpoints/01-results/large-traces):
`results.csv`, `manifest.json`, вывод прототипа, эталона и сверок. Manifest
содержит URL, SHA-256 входов и файлов реализации, ёмкости, число запросов и
правила измерения. Логи эталона содержат целые счётчики; старые логи без `EXACT`
можно читать прежним компаратором, но большой сценарий требует точные счётчики.

## Проверки разных сценариев

После сборки образа можно отдельно запустить набор без скачивания данных:

```sh
docker run --rm --network none --cpus 2 --memory 2g \
  --user "$(id -u):$(id -g)" \
  --mount "type=bind,src=$PWD,dst=/workspace" \
  nis-sieve:dev python3 tests/check_scenarios.py
```

Набор генерирует 12 профилей с фиксированным seed: один повторяющийся объект,
уникальное сканирование, циклы из 8 и 9 объектов, сканирование между горячими
обращениями, смену горячего набора, равномерную и неравномерную популярность,
смесь частых и одноразовых запросов, граничные 64-битные ID и два преобразования
того же потока. Для каждого профиля проверяются ёмкости 1, 2, 3, 7, 8, 9,
16, 64 и 129 — 108 точных сверок ARC с эталоном под ASan/UBSan.

Дополнительно проверяются известные ответы при полном размещении рабочего
набора и уникальном сканировании, повторяемость запуска, неизменность результата
после взаимно однозначного переименования ID и изменения игнорируемых ненулевых
размеров/меток времени. Результаты и хеши сгенерированных входов сохраняются в
[scenarios](nis/checkpoints/01-results/scenarios).

Отдельный отрицательный случай показывает ограничение эталона: записи с
размером 0 отбрасываются до применения `--ignore-obj-size 1`. Поэтому сравнение
с replay, читающим все ID, должно завершиться ошибкой из-за разного числа
запросов. После явного приведения размеров того же потока к 1 результаты снова
совпадают. Основные реальные префиксы не изменяются и не нормализуются этим тестом.

Быстрый `check_environment.py` также проверяет оба ghost-списка ARC,
изменение цели T1 в обе стороны и отказ на нулевой ёмкости. Компаратор
отклоняет невозможные счётчики, противоречащие им доли, дубли результатов
и повреждённые записи — одинаковые некорректные файлы не дают ложный успех.
